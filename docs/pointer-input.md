# 原生指针输入

`Event.pointer_down` 与 `pointer_up` 的负载是 `PointerButtonInput`：窗口局部逻辑坐标 `position`、`button`、当次 `modifiers` 和 `press`。旧调用者应将传给命中、编辑器或变换的点改为 `input.position`；转发事件时保留完整负载。当前 Content 原生交付仍为主按钮；其他按钮的原生按下会打断连续序列，尚未因此开放完整辅助按钮交互。

窗口构造时显式设置 `native_pointer_clicks=true`，才分配独立的原生按下状态。默认关闭，不为该可选状态分配内存。`PointerPress.sequence=0` 表示没有原生 receipt；原生时间戳为零仍是有效采样，二者不能混同。

`press.window_count` 是同一窗口的原始连续计数，按 1、2、3、1 循环，不表示某个控件的双击或三击。不同按钮、失焦、捕获转交、权限变化和未完成原生操作会打断连续性。一次按下的配对释放保留其序号和计数。移出原生距离阈值后再移回，不能恢复后续连续资格；这不取消当前普通点击应有的配对释放。

在实际原生 down/up 回调内调用 `window.pointerPressSnapshot(input.press, phase)`，读取拥有型的原始 `timing`、真实按钮和当前 `continuation_eligible`。该查询不分配、不调用 SDK；它严格核对线程、App、窗口代数、当前原生操作、阶段和 receipt。原生操作或窗口代数已失效、阶段或 receipt 不匹配，或处于遮蔽该入口的独立原生回调 scope 内，查询会失败。scope 返回后，原操作仍有效时可以继续查询。查询成功本身不授予控件或业务动作权限，receipt 不能用于稍后重放动作。

宿主显式拥有的拖动 deadline 可以调用 `window.pointerPressHeld(press, button)`，只检查同一窗口收到的 down 是否已经完成交付、仍保持按下。它核对主线程、存活窗口、输入许可、实际原生操作及完整 receipt；该次 down 尚未完成交付、已经开始 up、失焦/捕获取消、禁用、关闭或原生操作与所有者状态不一致时均不能沿用旧按下。移出点击连续距离阈值不会终止这个 held 事实。成功不返回原始时间、不创建事件权限，也不延长 `pointerPressSnapshot` 的回调范围；上层仍须独立核对控件身份、当前成功绘制快照及拖动所有权。它不分配、不查询 SDK，也不安装时钟。

`timing=null` 表示该入口没有可确认的原始时间/位置采样。Windows 直接 `SendMessage` 或未由框架分派的入口不会借用上一条队列消息的时间，也不会用回调执行时刻补造时间。有效原始时间使用原生毫秒计数及回绕规则；分类用位置、坐标域与阈值构成同一采样，不能拿局部 DIP 位置替换其中一个值。

`previous_completed_sequence` 仅在当前精确匹配的 down 中、仍有可连续的已完成原始历史时报告其序号，否则为零；up 始终为零。未知时间或移出阈值的按下仍可能完成当前普通动作，但不会留下这样的连续历史。该字段供独立 UI 所有者延迟核对连续性，不是所有已完成按下的日志。不能从窗口计数猜测该事实，也不能把它当控件身份或动作许可。控件连续计数需要显式目标身份、处理器代数和最近成功的命中快照；编辑器词/行选择属于这条上层桥接，原生计数本身不完成这些功能。

独立 C/SDK 回调必须使用 `App.beginNativeCallback()`，并在返回前结束 scope；它在保持 App 生命周期的同时，遮蔽被暂停的原始输入。窗口仍打开时可用 `Window.beginNativeCallback()`。这些 scope 不授予业务权限。普通组合与 Region 转发使用 `beginCallback()`，保留原有入口；不能把一次普通转发变成新的原生输入。

Windows 已实际检查队列采样、未知时间、按钮打断、捕获重入、首次聚焦及真实失焦后返回原窗；Linux 已通过实际 GTK C 信号入口到 Core 的两种优化、1x/2x 检查。隐藏原生测试不建立物理设备来源、视觉质量或输入到显示延迟结论。UI 注册控件与编辑器桥接继续分别验收。

## Linux 触摸屏

GTK 窗口的绘制区接收 GDK 的触摸（`GDK_TOUCH_MASK`、`touch-event` 信号），不再让 GTK 把第一根手指当作鼠标：轻点在落点发出一次主按钮点击；手指不动按住 500 毫秒以上抬起，按右键点击处理；手指移动超过 8 DIP 后不再算点按，而是让手下的内容跟着手指滚动（`Event.wheel`，delta 为像素，方向与滚动条滑块相反）；两根手指按中点移动滚动。被合成器拿走的触摸（`GDK_TOUCH_CANCEL`）既不滚动也不点击。点按的按下与抬起走鼠标同一条原生路径，焦点、抓取和按下 receipt 与鼠标点击相同；绘制区收到过触摸后，GTK 由触摸屏模拟出的按钮与移动事件会被丢弃，手指不会再拖选文本。核心没有缩放事件，双指捏合只滚动不缩放。手势规则在 `src/platform/linux_touch.h`，不依赖 GDK，由 `test-linux-touch` 覆盖；`smoke-linux-touch` 以 GDK 的触摸事件驱动真实窗口。
