# Pinned toolchain observations

The supported compiler remains Zig 0.15.2. The following is a locally reproduced compiler/backend issue, not a change to framework error identities or native callback ownership. No global LLVM override or toolchain upgrade is required by this workaround.

## Linux x86 Debug optional-error comparison

A main-thread diagnostic sink receives `Diagnostic` by value and compares its `err: ?anyerror` with a stored `?anyerror`. In the observed Linux x86_64 Debug code generated by the self-hosted backend, this expression can reject identical error payloads:

```zig
value.err == state.expected and value.err != null
```

The original hidden-window fixture logged `error.LayersRequired` for both values. Inspection of its preserved executable at the comparison showed the actual and expected payloads both equal to 156 (`0x009c`). The generated equality also loaded two unwritten stack bytes as optional-presence flags; in that execution those bytes differed (`0x00` and `0x7a`). The subsequent `err != null` used the correct zero-payload check. This explains why adding unrelated numeric diagnostic logging could change the failure without changing either error.

`tools/optional_error_probe.zig` is an independent reproducer using only the diagnostic value type, an explicit sink and caller-owned state. It creates no window, GUI runtime, worker or framework App. It is deliberately excluded from normal build/test targets. On the checked Linux x86_64 Zig 0.15.2 installation:

```sh
zig run -fno-llvm --dep diagnostics \
  -Mroot=tools/optional_error_probe.zig -Mdiagnostics=src/diagnostics.zig
# exits 1: comparison rejected actual=error.Example, expected=error.Example

zig run -fllvm --dep diagnostics \
  -Mroot=tools/optional_error_probe.zig -Mdiagnostics=src/diagnostics.zig
# exits 0: optional error comparison matched payloads
```

The full original fixture was preserved under the local ignored cache for inspection. Reproducer and LLVM runs establish this narrow backend pattern; they do not claim that every optional comparison or every Debug target is affected.

Native test sinks avoid the expression by explicitly unwrapping both optionals and comparing the actual `anyerror` payloads:

```zig
const matches = if (value.err) |actual|
    if (state.expected) |wanted| actual == wanted else false
else false;
```

These sinks require a non-null expected error, so either null correctly rejects the diagnostic. A sink that permits two null errors must handle that null/null case explicitly. The workaround preserves error identity checks; it never substitutes error-name strings or accepts unexpected diagnostics. Project inspection found the risky two-optional pattern in native test sinks; production diagnostic storage used null checks or unwrapped payloads. Keep that distinction when adding or reviewing future comparisons.
